# Public record verifier — design and feasibility (row14)

Outcome: a standalone Node24 CLI, zero third-party dependencies, verifies one ciphertext record using public Sui testnet GraphQL RPC and the public Walrus aggregator. Plain PASS/FAIL, exit0 only when every required check passes; no keys, decryption, DB, Simiri API, private facts or environment loading. New files only; base8adca4e2a. Exact file list was posted in PROGRESS before this file was written.

## Verified infrastructure and gap
The existing b56c49817 verifier is not present on this base. Its own README explicitly excludes checkpoint membership: the checkpoint manifest is encrypted. Its certification check compares caller-supplied reference certification fields with a real RootAdvanced event, but does not prove that the supplied record hash belongs to that checkpoint. Substituting another available blob and its matching hash can therefore pass those checks. Its freshness code also treats a superseded root or unreadable latest root as PASS; the new CLI must fail both.

The current publisher commits a flat canonical reference array, not a per-record Merkle tree. V2 computes `manifest.v2(records)` inside `checkpoint.v2(header,recordsCommitment)`, then `owner-root.v1(ownerRef,version,policy,checkpoint)`. A record's `certification` is attached after assembly; that copied object is not an inclusion proof. Source: financial-memory-owner-root-core.ts:568 and :923; older V1 similarly hashes the whole reference array. Public ciphertext bytes plus a record receipt cannot open those commitments without further evidence.

## Proposed implementation and decision boundary
1. Strict minimized JSON input: expected root/version/commitment/certifying transaction, pseudonymous ownerRef/account binding, selected public blob/patch locator and ciphertext hash. Reject fact text, credentials, unknown fields, URLs and oversized input before network access.
2. Pin the existing testnet package and the two public HTTPS endpoints. Verify successful transaction, exact historical OwnerRoot output and RootAdvanced event, checkpoint number, manifest pointer/hash and owner/account/network/policy binding. Follow bounded pages. Fetch selected ciphertext and manifest ciphertext; hash bytes locally. No signatures or validator-certificate independence is claimed: public RPC is the trust boundary.
3. Freshness: latest root query is mandatory, exact version AND commitment must still match; check certification timestamp, bounded clock skew and a default24h age limit. Missing/latest-query error/supersession fails. Plain reports show only fixed check codes and public root/version/time; never echo input/error bodies or pseudonymous ownerRef.
4. **Record inclusion cannot PASS from today's receipt alone.** Default must be `FAIL RECORD_INCLUSION_UNPROVEN`. A possible no-publisher-change extension accepts an explicitly supplied complete canonical metadata witness for the relevant V1 checkpoint or V2 segment chain, recomputes the exact existing commitments and proves the selected reference occurs. It needs no decryption in the CLI, but the witness exposes other records' opaque references, kinds, field paths and policy metadata. Those fields are currently inside encrypted manifests; they must not silently become public. A selective hash-only proof would require a separately approved commitment/publication change and is outside this new-files-only task.

**Claude decision01:34:44Z: APPROVED owner-opt-in complete metadata witness.** Accept full V1 checkpoint or V2 checkpoint segments plus restore policy, recompute their exact catalogue/checkpoint/root commitments, and require the selected reference and hash to match. The witness reveals opaque catalogue metadata, never fact contents. Missing evidence still fails closed. No exporter, publication, protocol change or disclosure is authorized or implemented here. The design does not invent an inclusion proof.
